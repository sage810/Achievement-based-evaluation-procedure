## 0. 한눈 요약

- 자료의 핵심 개념: **성취수준별 최소 능력자(MCP: Minimally Competent Person)** = "각 성취수준에 가까스로 도달한 학습자"(기준 성취율에 가까스로 도달한 학생). 성취기준마다 A~E의 MCP 수행 특성 진술문을 만들고, 그 수준을 대표하는 문항을 1개씩 개발.
- **1문항 = 1성취기준** 원칙. 예: [12정03-05](표준 입출력, 파일 입출력) 문항은 [12정03-06](다차원 데이터 구조) 요소를 포함하지 않음. "한 문항에서 여러 성취기준을 혼합하지 않고, 특정 성취기준만을 평가". (범위가 좁아 보일 수 있으나 성취기준별 성취수준을 정밀하게 측정하기 위함.)
- 지필평가(선택형): 성취기준마다 A, B, C, D, E 각 1문항(총 5문항)이 기본 구성. 각 문항은 "점검을 목표로 하는 성취수준"을 가짐.
- **난이도 기준**: 선택형 = 목표 성취수준 학생의 약 **2/3(≈66%)** 가 정답. 서·논술형 = 해당 성취수준 학생이 문항별 **만점을 받을 확률 약 50%**.
- 수행평가(논술형 포함): 채점기준표에 성취수준-수행 수준-배점을 연계하고 **성취수준별 분할점수(A/B, B/C, C/D, D/E, E/미도달)** 를 명시 → 점수만으로 수준 판별.
- 성취율 구간: A 90% 이상, B 80~90%, C 70~80%, D 60~70%, E 40~60%, 미도달 40% 미만. (원문: "성취수준 B(성취율 80% 이상 90% 미만)", "최소 성취수준 … 학업 성취율 40% 이상~60% 미만")
- AI 서·논술형 평가 시스템에서 활용할 수 있는 문항과 채점기준표도 함께 제시했다고 명시(p.8).
- 수록 범위: 지필(선택형) 23개 성취기준 × 5문항 = 115문항 — [12정01-01~03] 컴퓨팅 시스템, [12정02-01~04] 데이터, [12정03-01~10] 알고리즘과 프로그래밍, [12정04-01~03] 인공지능, [12정05-01~03] 디지털 문화. 수행평가/논술형 5과제 — [12정02-04] 실험·실습, [12정03-07] 논술, [12정03-09] 실험·실습+논술, [12정04-03] 논술, [12정05-03] 논술 (→ 4장).
- 추출 한계: 그림 선지(아바타·캐릭터 등)와 그래프 이미지는 텍스트로 없음 — 해당 문항은 해설로 정답 근거만 기록. 분할점수 표 2곳은 글리프 위치로 해독(4.1, 4.5 참조).

### 1.2 서문 (p.2) 요지
- 2022 개정 「정보」 기반, 성취기준별 성취수준을 확인할 수 있는 MCP 진술문 + 대표 문항 수록.
- "성취수준별 최소 능력자(MCP) 진술문은 각 성취수준별로 기준 성취율에 도달한 최소 능력자가 알거나, 할 수 있는 수행 특성을 진술함으로써, 성취수준 판별의 준거가 됩니다."
- 각 문항은 하나의 성취기준에 초점, 해당 성취기준별 성취수준(A~E)을 평가하도록 설계.
- 목적: 성취수준 정확 판별, 평가 신뢰도 제고, 수업-평가 연계, 학생 맞춤형 피드백.

### 1.3 "평가의 준거를 묻고, 학생의 역량으로 답하다" (p.6~8) — Why/How/What
- Why: 성취평가제는 모든 학생이 학습 위치를 확인하고 학습 경로를 설계하도록 돕는 평가 지향. 현재 절대·상대평가 병행으로 취지 구현 미흡, 일부 학생만 변별하는 한계 → 모든 학생의 학업 수준을 객관적·구체적으로 파악하는 체제 필요.
- How:
  - (1) MCP를 고려한 성취수준별 대표 문항 제작: 성취기준·성취수준 분석 → 평가 요소 도출 → 개발위원 합의로 각 성취수준 대표 문항. "해당 성취수준을 대표하는 문항은 성취수준 진술문과 예상 정답률을 고려하여 개발".
  - (2) 평가 요소에 적합한 평가 방법 설계: 지식·이해, 과정·기능, 가치·태도 범주에서 평가 요소 추출 → 선택형 문항, 수행평가 과제, 논술형 평가 문항 개발, 교과 특성을 반영한 채점 기준표로 성취수준별 수행 특성 제시. "선택형 문항은 목표 성취수준 학습자의 약 2/3가 정답을 맞출 수 있도록 난이도를 조정하였으며, 수행평가 문항은 분할점수를 채점기준표에 구체적으로 명시하여 점수만으로도 수준 판별이 가능하게 하였습니다."
- What: 학생(성취 수준 파악·성찰·학습 계획), 교사(맞춤형 피드백 지표, 교수학습 개선), 교육과정–수업–평가–기록 연계, 학부모(공정·신뢰성 높은 결과). "AI 서·논술형 평가 시스템에서 활용할 수 있는 문항과 채점 기준표도 함께 제시". 학교 교과·교육과정 협의회로 이어지길 기대, 절대평가 전환·역량평가 대입 개편의 동력 기대.

## 2. 평가도구 개발 원리·규칙

### 2.1 일반적 방향 (p.10)
- 성취기준, 성취기준별 성취수준, 영역별 성취수준, 학기 단위 성취수준을 반영해 설계. 학교수준 교육과정에서 재진술 → '모든' 성취수준을 점검할 수 있는 평가도구.
- 모든 성취수준을 고르게 점검 (특정 수준 집중 금지).
- 지필평가: 다양한 난이도 문항을 골고루 포함, "기존의 상위 수준 학생만 변별하는 평가 방식은 지양".
- 수행평가 도구·채점기준: 모든 성취수준 판별. 성취기준·성취수준의 지식·이해/과정·기능/가치·태도 범주 내용 요소 분석 + '성취기준 해설', '성취기준 적용 시 고려 사항' 종합 → 평가 요소 도출 → 평가 요소별 수행 수준(채점기준)과 배점 설정. "채점기준은 명확하고 일관성 있게 작성되어야 하며 임의적 배점 부여, 기본점수의 과도한 부여를 지양해야 합니다."
- 핵심 포인트: 평가 운영 계획의 체계화 / 성취수준 기반 설계(A~E 수준에 맞춘 문항 구성) / 평가의 다양성(문항 유형, 난이도, 배점 다양화).

### 2.2 개발 절차 5단계 (p.11~12)
① 평가도구 개발의 기본 방향 설정 (교과협의회, 학기 단위 성취수준 진술 → 수준별 문항 출제 계획)
② 평가 문항 및 과제의 난이도 설정 (각 성취수준 도달 여부 판단에 타당 + 모든 성취수준 평가)
③ 성취수준과 문항 난이도 수준의 연계 (연습: 기출 문항·학생 응답 자료로 예상 정답률/예상 점수를 예측해 실제와 비교)
④ 지필평가 도구 개발 / 수행평가 도구 및 채점기준 개발 (수행평가 적합성 검토, 능력의 전 범위 평가, 채점기준표에 평가요소와 요소별 수준(척도, 범주) 제시)
⑤ 평가도구 검토 및 확정 (교과(학년)협의회 공동 검토; 교육과정 범위 이탈 여부, 특정 학생 유불리, 문항 제작 원리, 문항 오류 확인)

### 2.3 주요 고려 사항 (p.12~15)
**지필평가**: "개별 문항은 특정 성취수준을 판별할 수 있도록 하되, 평가도구 전체에는 다양한 수준의 문항이 고르게 분포되도록 개발"
- (선택형 문항) 성취수준별 약 2/3의 학생이 정답을 맞힐 수 있는 난이도.
- (서·논술형 문항) 해당 성취수준의 학생들이 문항별 만점을 받을 확률이 약 50%.
- 근거(참고사항 Q&A): NAEP 보고서 — '충분한 숙달(sufficient mastery)'은 학습 내용의 대체로 50~80% 습득. 숙달 수준을 문항 정답 확률로 해석. 국가수준 학업성취도 평가도 이 기준 사용(정구향 외, 2004; 김경희 외, 2003). 한국교육과정평가원 워킹그룹이 선택형 2/3, 서·논술형 만점 확률 50%로 설정. 출처: 성취평가 평가도구 개발예시, 교육부·KICE, 2024.
- 성취수준별 문항이 고르게 포함된 균형 잡힌 도구.

**수행평가 과제** (p.14)
- 성취기준 적합성 검토; 목표 학습 성과가 명확히 드러나게; 모든 성취수준 학생이 역량에 따라 수행·평가받도록.
- 내용·유형 설계: 성취기준, 평가 요소, 인지적 사고 수준 → 개인/모둠, 과제 구조화 정도, 소요 시간 등. 과제 구조와 시행 정보 명확히 제시.
- **최소 성취수준 학생을 위한 과제**: "학업 성취율 40% 이상~60% 미만의 학생들도 수행할 수 있는 과제를 포함하도록 설계합니다. 단순히 기본점수를 부여하는 방식이 아닌 실제로 최소 성취수준 학생들이 수행할 수 있는 난이도와 유형으로 개발해야 합니다."
- 유의사항: 확인하려는 것과 관련성 낮은 부차적 지식·기능을 요구하지 않도록 교과협의회에서 여러 번 검토.

**채점기준** (p.15)
- 채점기준표 = 평가 요소 + 각 성취수준에 대한 기대 수행이 제시된 수행 수준(채점기준) + 배점.
- (평가 요소) 성취기준·성취기준별 성취수준·영역별 성취수준·학기 단위 성취수준을 고려해 지식·이해/과정·기능/가치·태도 범주의 내용 요소로부터 추출.
- (수행 수준) 학기 단위 성취수준과 연계되도록 구분, 평가 요소별 수준 차이 명확히. 차이가 드러나지 않으면 수준을 합치거나 늘릴 수 있음. 각 수준의 특성이 질적으로 구분되도록. 학생의 해결 과정·응답(수행/산출물)을 구체적으로 구상·예측하여 차별적 특성 파악.
- (배점) 각 성취수준의 기준 성취율 이상 도달 시 관찰 가능한 수행 특성에 따라 배점. 예: 90% 이상 도달 시 관찰 가능한 수행 특성을 보이는 학생에게 만점.

### 2.4 경기 표준화 평가도구의 차별점 (p.18)
- 성취기준 + 성취수준 고려. 성취기준을 내용 체계에 근거해 3범주(지식⋅이해, 과정⋅기능, 가치⋅태도)로 분석 → 평가 요소 추출.
- 모든 성취기준별 성취수준 진술문 분석 → 각 성취수준별 최소 능력자 특성 합의·진술.
- 평가 요소 + MCP 특성 → 적합한 평가 방법(지필/수행) 및 평가 유형(선택형 문항, 논술형 문항, 수행평가 과제) 결정.
- 상대평가: '누가 몇 점, 석차' ↔ 성취평가: "누가 어느 성취수준에서 무엇을 알고 할 수 있는지 증거를 수집하여 피드백".
- 선택형: 정답 가능성 약 66%로 예상되는 성취수준을 '점검을 목표로 하는 성취수준'으로. 논술형·수행평가: 응답 다양·교사 전문 판단 필요 → 각 성취수준별 수행 수준을 채점기준표로.

### 2.5 개발 절차와 과정 (p.19~20)
- 성취기준별 성취수준 = 출제의 내용적 준거. 성취수준 진술문 간 내용적 경계선 명료화 → 각 수준 대표 문항 1개.
- <그림> 성취수준 B 대표 문항 출제 범위 = "성취수준 B의 최소 능력자의 특성"(80% 선) ~ "성취수준 A의 최소 능력자의 특성"(90% 선) 사이.
- Q&A: MCP 진술 필요 이유 → 출제 근거·범위 명확, 현장 변형 시 내용 복잡성·깊이 조절 참고. MCP 진술은 절대 기준 아님(합의 결과물, 모든 학교에 일률 적용 아님).
- 평가 요소 도출 자료: 성취기준, 성취기준별 성취수준, 성취기준 해설, 성취기준 적용 시 고려 사항, 내용 체계 3범주.
- '점검을 목표로 하는 성취수준' 결정:
  - 선택형: 문항별 평가 요소, 판별하려는 성취수준, MCP 수행 특성 제시 + 문항을 맞힌 학생에게 기대되는 성취수준·기대 능력 기술.
  - 수행평가 과제(논술형 포함): 평가 요소별로 각 성취수준 학생에게 기대되는 수행 수준 진술. 연계 방식: ① 1성취수준–1수행수준, ② 1성취수준–2개 이상 수행수준, ③ 2개 이상 성취수준을 묶어 1수행수준 (예: "A-C", "D-E", "A-B").

### 2.6 성취수준 판별 방법 (p.20~21)
- 선택형: 목표 수준이 A의 MCP이면 "성취수준 A의 최소 능력자의 2/3(66%)가 정답을 맞힐 것으로 예상되는 난이도를 가진 문항". 문항 표적 수준을 알면 분할점수(준거점수)를 합리적으로 결정·추정 가능.
- 수행평가: 채점기준표에 분할점수 명시. 예: 20점 만점, A 분할점수 17점 → A 능력 학생은 최소 17점 예상; 16점=B, 17점=A.
- **분할점수 산출 공식(추정분할점수)**: 각 성취수준 MCP가 평가 요소별로 받을 점수의 합 = 그 수준의 분할점수.
- 예시 <표-1> 수행평가(논술형 포함) 채점기준표:

| 문항 | 평가 요소 | 성취수준 | 수행 수준 | 배점 |
|---|---|---|---|---|
| 1 | 평가요소1 | A-C | 성취수준 C 최소 능력자 수준 | 6 |
| | | D | D 최대 능력자 수준 / D 최소 능력자 수준 | 5 / 4 |
| | | E | E 최대 / 중간 / 최소 능력자 수준 | 3 / 2 / 1 |
| 2 | 평가요소2 | A | A 최대 / 중간 / 최소 능력자 수준 | 8 / 7 / 6 |
| | | B | B 최대 / 최소 | 5 / 4 |
| | | C | C 최소 | 3 |
| | | D-E | E 최소 | 2 |

  <표-2> 분할점수: A/B 12, B/C 10, C/D 9, D/E 6, E/미도달 3. (A MCP: 6+6=12; B MCP: 6+4=10; C: 6+3=9; D: 4+2=6; E: 1+2=3) → 11점이면 B.

  - ③교육과정 분석: '성취기준 해설'과 '성취기준 적용 시 고려 사항'

### [12정01-01] 유무선 네트워크 (영역: 컴퓨팅 시스템) p.32~39
- 성취기준: 유무선 네트워크의 특성을 이해하고, 컴퓨팅 시스템 간 공유, 협력, 소통을 위한 네트워크 환경을 구성한다.
- 성취수준:
  - A: 유무선 네트워크의 특성을 정확하게 설명하고, 컴퓨팅 시스템 간의 네트워크 구성 및 공유 설정으로 협력적 의사소통을 위해 네트워크 환경을 적극적으로 활용하려는 자세를 갖출 수 있다.
  - B: …정확하게 설명하고, …부분적인 네트워크 구성 및 공유 설정으로 … 활용하려는 자세를 갖출 수 있다.
  - C: …특성을 설명하고, …부분적으로 네트워크 구성 및 공유 설정으로 … 활용하려는 자세를 갖출 수 있다.
  - D: …특성을 설명하고, …부분적 공유 설정으로 협력적 의사소통을 위한 네트워크 환경 활용의 필요성을 수용할 수 있다.
  - E: 유무선 네트워크의 특성을 인지하고, 컴퓨팅 시스템 간의 부분적으로 공유 설정할 수 있다.
- 성취기준 해설: 유무선 네트워크의 특성 등을 구체적인 예를 들어 설명하고, 컴퓨팅 시스템에서 활용 가능한 유무선 네트워크 환경을 구성.
- 내용 요소: 지식·이해 유무선 네트워크의 특성 / 과정·기능 컴퓨팅 시스템 간 네트워크를 구성하고 공유 설정하기 / 가치·태도 협력적 의사 소통을 위해 네트워크 환경을 적극적으로 활용하는 자세
- 평가 요소: 유무선 네트워크의 특성 설명하기 / 컴퓨팅 시스템 간의 네트워크 구성하기 / 협력적 의사소통을 위한 네트워크 환경 활용하는 자세 갖기
- 문항 개요: 1(A) 세 요소 모두, 2(B) 특성+구성, 3(C)·4(D)·5(E) 특성 설명
- MCP: A 정확 설명+구성·공유 설정+활용 자세 / B 정확 설명+일부 구성·공유 설정 / C 설명+일부 공유 설정 / D "유무선 네트워크의 특성을 알고, 컴퓨팅 시스템 간의 부분적인 공유 설정을 할 수 있다." / E "유무선 네트워크의 특성을 알 수 있다."
- 문항:
  1. (A) 동아리실 공동 과제 그림 + <동아리 일지>(공유 폴더 설정, 같은 Wi-Fi, 공동 문서 편집). "네트워크 구성과 공유 환경에 대한 설명으로 옳은 것만을 <보기>에서 있는 대로 고른 것은?" ㄱ 실시간 협업 ㄴ 공유 설정 없이 자동 접근(오) ㄷ 무선으로 여러 기기 동시 접근 ㄹ 파일·프린터 자원 공유 → 정답 ④ ㄱ,ㄷ,ㄹ.

### [12정03-01] 문제 분해·모델링 (영역: 알고리즘과 프로그래밍) p.88~95
- 성취기준: 복잡한 문제를 해결 가능한 작은 문제로 분해하고 모델링한다.
- 성취수준:
  - A: 문제 분해와 모델링 적용 방법을 설명하고, 문제를 해결 가능한 작은 단위의 문제로 효율적으로 분해하고, 컴퓨팅 시스템에서 처리 가능한 단순화나 구조화된 형태로 적합하게 모델링하여 문제 해결을 위한 모델로 적극적으로 표현하려는 자세를 내면화할 수 있다.
  - B: 문제 분해와 모델링 적용 방법을 설명하고, 문제를 해결 가능한 작은 문제로 분해하고, … 모델링하여 … 자세를 인식할 수 있다.
  - C: 문제 분해와 모델링의 원리를 설명하고, … 자세를 인식할 수 있다.
  - D: 문제 분해와 모델링의 원리를 설명하고, 문제를 작은 문제로 일부 분해하거나 구조화된 형태로 부분적으로 모델링하여 … 자세를 수용할 수 있다.
  - E: 문제 분해와 모델링의 개념을 인지하고, 문제를 작은 문제로 일부 분해하거나 구조화된 형태로 부분적으로 모델링할 수 있다.
- 성취기준 해설: "복잡한 문제를 분석하는 단계에서 좀 더 작은 문제로 분해하는 과정을 수행하며, 해결하기 용이하도록 단순화나 구조화하는 모델링 단계를 수행할 수 있어야 한다."
- 적용 시 고려: 작은 문제 해결 결과 종합 시 전체 문제 해결이 원활한지·오류 없는지 확인. "제시된 문제 상황을 컴퓨팅 시스템으로 해결할 수 있도록 문제 분해, 모델링, 알고리즘 설계 등의 추상화 과정 및 프로그램 작성, 실행 결과 평가, 오류 수정 등의 자동화 과정이 유기적으로 연결되도록 나선형으로 교수⋅학습을 제시하고 과정 전반을 평가하도록 한다."
- 내용 요소: 문제 분해와 모델링 / 문제를 분해하고 모델링하기 / 문제 해결 모델을 구성하고 적극적으로 표현하는 자세
- 평가 요소: 문제를 해결 가능한 작은 단위로 분해하기 / 문제 모델링하기 (A·B 둘 다, C~E 분해하기)
- MCP: A "…실생활 문제를 해결 가능한 작은 단위의 문제로 효율적으로 분해하고 … 적극적으로 표현하려는 자세를 실천" / B "…구조화된 형태로 단순화나 모델링하여 … 표현하려는 자세를 인식" / C "문제 분해와 모델링의 주요 원리를 설명하고, … 단순한 형태로 모델링하여 …인식" / D "주요 원리를 설명하고, 문제를 작은 문제로 일부 분해하거나 구조화된 형태로 부분적으로 모델링할 수 있다." / E "문제 분해와 모델링의 개념을 알 수 있다."
- 핵심 개념(해설 반복 문구): "문제는 해결이 필요한 모든 것을 의미하며 현재 상태와 목표 상태의 차이로 인해 발생한다. 문제 분해는 서로 관련 있는 작은 문제로 분해하는 과정이고 모델링은 핵심적인 요소를 제외한 나머지 요소를 제거하는 과정이다. 모델링은 추상화 과정을 통해 추출된 요소들의 관계를 쉽게 표현하기 위해 표, 그래프, 트리 등 다양한 형태로 구조화할 수 있다." / "컴퓨터로 문제를 해결하기 위해서는 추상화, 알고리즘 설계, 자동화의 절차가 필요하다."
- 문항:
  1. (A) 축제 복불복 주사위(짝수면 "선물 뽑기 기회를 한 번 더 제공합니다", 홀수면 "종료합니다"). "<문제 상황>을 컴퓨팅 시스템을 활용하여 해결하고자 할 때, 옳은 것만을 <보기>에서 있는 대로 고른 것은?" → ④ ㄱ(핵심 요소=주사위 숫자, 짝·홀 판별), ㄹ(2로 나누어 떨어지면 짝수), ㅁ(목표 상태=기회 제공/종료 결정된 상태). ㄷ "현재 상태는 판별 가능한 상태" 오(현재 상태=모르는 상태). 판단: "현재 상태와 목표 상태 설정하기, 핵심 요소 찾기, 처리 가능한 구조화된 형태로 모델링을 할 수 있음을 의미함."
  2. (B) 컴퓨팅 문제 해결 <보기> → ⑤ ㄷ(지각 문제 → 기상, 등교 준비, 교통으로 분해), ㅁ(3시간 이상 경고 → 목표 상태=3시간 이하). 오답: ㄱ 모델링 후 현재·목표 상태 정의(순서 오), ㄴ 엘리베이터 소리=모델링(오, 시스템 동작), ㄹ 도서관 이동=현재 상태(오, 전략).
  3. (C) "문제 분해와 모델링에 대한 설명으로 적절하지 않은 것은?" → ① 분해된 문제를 해결하면 전체 문제를 항상 해결(오; 관계·통합 고려).
  4. (D) 추상화 (가) 문제 분해, (나) 모델링 → ④.
  5. (E) 두 친구 대화 빈칸 → ① 분해.

- 문항 1: ⋅문제: 하루 물 섭취량 계산기 ⋅문제 상황: "현대인들은 바쁜 생활 속에서 충분한 물을 마시지 못하는 경우가 많다. 특히 체중과 활동량에 따라 필요한 하루 물 섭취량이 달라지지만, 이를 스스로 계산해 관리하는 것은 번거롭다. 사용자가 자신의 체중과 하루 활동량을 입력하면 하루 권장 물 섭취량을 계산해 주고, 알림 메시지를 통해 물 마시기를 독려하는 프로그램이 필요하다. 이를 통해 반복적이고 수치 기반의 건강 관리가 가능해질 것이다."
- 문항 2: 변수 설계표(변수명 | 역할 설명 | 데이터형): weight 사용자 체중 입력(kg) float / exercise 하루 운동 시간 입력(분) int / baseWater 체중 기반 기본 섭취량(ml) float / extraWater 운동 시간에 따른 추가 섭취량(ml) float / totalWater 최종 권장 섭취량(ml) float. 알고리즘 설계: 1. 체중(kg)과 하루 운동 시간(분) 입력 2. 음수나 문자가 입력되면 오류 메시지 출력 후 1로 3. 기본 섭취량 = 체중 * 30 (1kg당 30ml) 4. 추가 섭취량 = (운동 시간 // 30) * 350 (30분마다 350ml) 5. 총 섭취량 = 기본+추가 6. 2000ml 초과 시 2000ml로 제한 7. 최종 물 섭취량(ml) 출력.
- 문항 3 (코드 요지):

```python
while True:
    print("=== 하루 물 섭취량 계산기 ===")
    weight_input = input("체중(kg)을 입력하세요: ")
    exercise_input = input("하루 운동 시간(분)을 입력하세요: ")
    # 입력값을 숫자로 변환
    try:
        weight = float(weight_input)
        exercise = int(exercise_input)
        if weight < 0 or exercise < 0:
            print("음수는 입력할 수 없습니다.\n")
            continue
        # 물 섭취량 계산
        baseWater = weight * 30
        extraWater = (exercise // 30) * 350
        totalWater = baseWater + extraWater
        if totalWater > 2000:
            totalWater = 2000
        print(f"하루 권장 물 섭취량은 {totalWater:.1f} ml입니다.")
        break
    except ValueError:
        print("숫자를 정확히 입력하세요.\n")
```

## 5. 생성 시 따라야 할 규칙·문체 (재사용 템플릿)

### 5.1 설계 원칙 체크리스트
1. **1문항 1성취기준**: 한 문항(과제)에서 다른 성취기준 요소를 섞지 않는다. (예: 입출력 문항에 다차원 리스트 넣지 않기)
2. 평가 요소는 [성취기준 해설] + [성취기준 적용 시 고려 사항] + 내용 체계 3범주(지식·이해 / 과정·기능 / 가치·태도)에서 도출. 평가 요소 문구는 "~하기" 명사형 동사구 (예: "데이터 시각화 결과 분석하기", "적용 가능한 기계학습 유형과 이유 제시하기").
3. 성취수준 A~E 모두 점검. 지필은 수준별 대표 문항, 논술·수행은 채점기준표 내 수행 수준이 A~E를 모두 커버(묶음 허용: A-B, B-C, C-D, D-E, A-C).
4. 난이도 목표: 선택형 = 목표 수준 MCP의 약 2/3 정답; 서·논술형 = 해당 수준 학생의 문항 만점 확률 약 50%.
5. 최소 성취수준(E, 성취율 40~60%) 학생도 실제로 수행 가능한 하위 문항·수행 수준을 반드시 포함. "단순히 기본점수를 부여하는 방식"은 금지, "임의적 배점 부여, 기본점수의 과도한 부여를 지양".
6. 채점기준표에서 학업 성취율 40% 미만 구간은 생략하고 각주 "※ 학업 성취율 40% 미만의 수행 수준(채점기준) 및 배점은 생략함." 을 붙인다. → E 수준 최저 배점도 1점 이상(때로 2~3점)이며 0점 행 없음.
7. **분할점수(추정분할점수 방식)**: 각 평가 요소에서 해당 수준 '최소 능력자'에게 주는 배점(그 수준 행 중 가장 낮은 점수)을 합산 → A/B, B/C, C/D, D/E, E/미도달. 묶인 수준(B-C 등)은 두 수준 모두 같은 점수. 표기: "성취수준별 분할점수 [NN점 만점]" + 5칸 표.
8. 같은 수준 안에서 '최대/중간/최소 능력자'를 구분해 행을 2~3개 둘 수 있음(A 5점·4점 등). 수준 경계는 질적으로 구분되어야 하며, 차이가 안 드러나면 수준을 합치거나 늘린다.
9. 예시 답안은 보통 **A 수준 최소 능력자** 기준으로 작성하고 각주 "※ 예시 답안은 ( A )의 최소 능력자의 수행 특성을 고려하여 작성하였음." (실험·실습은 "예시 응답 자료").
10. 하나의 실생활 맥락(제시문/데이터/코드)을 여러 하위 문항이 공유하고, 하위 문항이 '해석 → 분석 → 작성/제안' 또는 '정의 → 설계 → 구현' 순으로 인지 수준이 올라가게 구성.
11. 교수·학습–평가 연계: 진단평가 → 형성평가 → 수행평가 차시 흐름, 차시마다 교사 피드백을 하위 수준/상위 수준으로 나눠 기술, 마지막에 "채점 기준의 수행수준과 연계", "최소 성취수준 보장 연계 피드백 방안".

### 5.2 문항(발문) 템플릿
- 도입: "다음을 읽고 물음에 답하시오. [NN점]" / "[1~2] 다음을 읽고 물음에 답하시오. [20점]" / "■ [가]와 [나]는 ~이 필요한 상황이다. 다음을 읽고 물음에 답하시오. [14점]" / "※ 다음은 ~ 데이터와 데이터 속성의 설명 자료이다. 물음에 답하시오."
- 하위 문항 동사: "~을 순서대로 작성하시오.", "~이유를 <조건>에 맞게 서술하시오.", "~를 완성하시오.", "~을 <조건>에 맞게 세우시오/정의하시오/설계하시오/구현하시오.", "~를 찾아서 작성하고, 각 ~의 필요성을 구체적으로 서술하시오.", "~을 제시하시오.", "~ 중 하나를 선택하고 그 이유를 제시하시오.", "~을 판단하고 근거를 제시하시오."
- 각 하위 문항 끝에 배점 "[6점]" 표기.
- 〈조 건〉 블록: "⋅~할 것." 형식의 불릿 2~5개. 자주 쓰는 조건: 선택지 제한("⌈디도스, 악성코드, 해킹, 파밍⌋중 1가지를 선택할 것."), 개수 지정("이유 2가지를 작성할 것.", "변수 3개 이상을 계획하여"), 근거 지정("i가 2, 10일 때 실행 결과를 이용할 것.", "[가]와 관련지어 그 특징을 구체적으로 작성할 것."), 형식 지정("(가설의 진술 형식) (예) ○○가 ~ 할수록 △△는 ~ 할 것이다."), 산출물 형식("파이썬 프로그램으로 프로그래밍하여 파일로 제출할 것.", "데이터 시각화 결과를 캡처하여 답지에 넣을 것.").
- 답란 틀: "⋅선택한 속성: ⋅가설: ⋅이유:", "∘핵심 요소1 ∘핵심 요소1에 대한 근거 …", "1) 정보보안 위협 요소: ____ 2) 특징: ____", "⋅문제 정의: ⋅문제 상황:".
- 제시문은 실제 뉴스 재구성 + "[출처] OO신문 (URL)" 표기.

### 5.3 채점기준(수행 수준) 문장 패턴
- 종결: "~함." (명사형 종결) / 정보보안 과제는 "~한 경우".
- 수준 구분 어휘 사다리:
  - 정도 부사: 명확하게·구체적으로·논리적으로(A) → 명확하게/논리적으로(B) → 타당하게·설명함(C) → 부분적으로 타당하게·간단히·일부(D) → 제시함/언급하나 미흡함/일부 사용(E)
  - 예: "그 이유를 논리적이고 구체적으로 서술함(A) / 논리적으로 서술함(B) / 타당하게 서술함(C) / 부분적으로 타당하게 서술함(D) / ~ 중 하나를 제시함(E)"
  - 예: "명확하고 타당하게 가설을 제시하고, 그 이유를 … 구체적이고 논리적으로 설명함(A)" → "타당하게 … 부분적으로 타당하게 설명함(B-C)" → "가설을 제시함(E)"
- 개수 기준: "5개 모두(A) / 5개 중 4개(B) / 3개(C) / 2개(D) / 1개(E)", "핵심 요소 2가지(A-B) / 1가지(C-D) / 부분적(E)", "4개의 코드 모두 / 3개 / 2개 / 1개".
- 2축 기준: "원인(코드 구조)과 영향(출력 결과)을 명확히 제시함", "목적과 타겟을 모두 구체적이고 명확하게(A) / 목적은 명확, 타겟은 다소 모호(B-C) / 타겟은 명확, 목적은 다소 미흡(D) / 모두 미흡(E)", "위협 요소 명확 + 특징 구체(A) / 하나만 충족(B-C) / 제시 + 특징 미흡(D) / 위협 요소만 미흡하게(E)".
- 수행 수준은 MCP 진술과 연계(예: A "오류 없이", C "기본적인/간단한", D "일부/부분적으로", E "개념을 알 수 있다" 수준).

### 5.4 MCP·성취수준 진술 문체
- 성취수준(교육부 진술) 동사 위계(가치·태도 축): 내면화할 수 있다(A) → 인식할 수 있다(B·C) → 수용할 수 있다/공감할 수 있다(D) → (E는 태도 생략, 인지·부분 수행만).
- MCP(경기 개발진 진술) 동사 위계: 실천할 수 있다 / 자기 주도적으로 실천 / 주도적으로 실천(A) → 인식할 수 있다 / 중요성을 알 수 있다 / 필요성을 알 수 있다(B·C) → 받아들일 수 있다 / 공감할 수 있다(D) → "~의 개념을 알 수 있다."(E, 거의 항상)
- 지식 축: 정확하게/명확하게 설명(A·B) → 설명(C) → 인지(D·E) / MCP: 설명 → 기본 사용법을 설명 → 기본 사용법을 알고 → 개념을 알고 → 개념을 알 수 있다.
- 기능 축(프로그래밍): 효율적으로/오류 없이 작성(A) → 작성(B) → 간단한/기본적인 프로그램 작성(C) → 일부/부분적으로 작성(D) → 인지(E).
- 수식어 사다리: 다양한 → (없음) → 일부/부분적으로 / 주어진 / 제시된 / 기본적인.

### 5.5 출제 의도(개발 방향) 문체
- 지필 2문장 공식: "⋅평가 요소의 [평가 요소]를 [할 수 있는지] 판별하는 문항임." + "⋅N번 문항은 성취수준 X를 고려한 것으로 이 문항을 맞힌 학생은 [MCP 수준 능력]할 수 있을 것으로 판단함/판단됨." (변형: "~능력을 갖추었음을 의미함", "~수 있음을 의미함", "~보여 준다고 판단함")
- 선택적 3번째 문장: 난이도·확장("난이도는 상 수준이며, 개념적 지식과 실용적 판단을 동시에 요구함.", "난이도는 매우 낮은 기초 수준으로, … 진단평가 또는 최소 성취수준 판별 문항임.", "유사 문항을 개발할 때는 … 확장할 수 있음.", "향후 조건문 포함 확장 문항, 오류 수정형 문항, 출력결과 추론형 문항 등으로도 확장 가능함.", "… 사전 인식 점검용으로도 활용 가능함.").
- 수행/논술 개발 방향: "~하는 사고력과 창의적 문제 설정 능력을 평가함.", "~할 수 있는 능력을 점검함.", "~까지 고려하는 비판적 사고력을 평가함.", "~태도 형성도 중요하게 고려함.", "평가 과정은 단편적인 정답이 아닌, ~의 일관된 논리 전개 능력에 초점을 둠.", "본 평가는 ~능력, ~능력, …, ~노력과 태도를 파악하고자 함.", "~종합적으로 점검함.", "~안내함." / 유의 사항 형식 "[소제목]: [설명]".

### 5.6 피드백 문체 (교사 피드백 칸)
- 하위/상위 이원화: "학습에 어려움을 겪는 하위 성취수준 학생에게 ~하기" / "학습 능력이 탁월한/우수한 상위 성취수준 학생에게 ~하기", "하위 수준 학생: ~지도함. ~제시할 수 있음. ~템플릿 제공 가능" / "상위 수준 학생: ~확장 과제 부여. ~심화 개념 적용 지도."
- 최소 성취수준 보장 장치(반복 등장): 미리 제작된 코드 제공, 온라인 플랫폼(프로그램 자동 평가 시스템, AIDT)·학습 관리 시스템의 수준별 추가 실습, 템플릿·매칭표·체크리스트·서술 문장 구조 예시 제공, 예시 기반 재작성 유도, 기본 기능부터 단계별 구현, 오류 디버깅 과정 안내.
- 피드백 진술은 "~하기", "~함", "~안내함", "~제공함" 명사형/개조식.

### 5.7 선택형 발문·선지 패턴(참고)
- "~에 대한 설명으로 옳은 것만을 <보기>에서 있는 대로 고른 것은?" (A·B, ㄱ~ㅁ 4~5개)
- "~으로 옳은 것만을 <보기>에서 고른 것은?" / "~으로 적절하지 않은 것은?" / "~으로 가장 적절한 것은?"
- "옳은 내용을 말하고 있는 사람만을 있는 대로 고른 것은?"(갑·을·병 말풍선)
- "(가)와 (나)에 들어갈 ~이 바르게 짝지어진 것은?" / "㉠에 들어갈 코드로 옳은 것은?" / "다음 프로그램의 실행 결과로 옳은 것은?"
- 게임형: "설명이 맞으면 아이템을 획득한다. 최종 아바타의 모습으로 옳은 것은?", 가로세로 퀴즈, 퀴즈 장면.
- E 수준은 거의 항상 "다음에서 설명하는 용어(기술)로 옳은 것은?" 개념 정의 문항 또는 "두 친구의 대화 주제로 가장 적절한 것은?"
- 같은 소재를 A→E로 단순화 재사용(걸음 수-칼로리, 1~n 합, 스마트폰-수면-만족도 데이터).

### 5.8 원문 오류·주의점 메모 (생성 시 그대로 베끼지 말 것)
- [12정03-10] 1번 <보기> ㄱ "n이 10인 경우 두 프로그램 모두 5050" — 실제 55(5050은 n=100). 정답 ④에 ㄱ 포함 → 원문 오류.
- [12정03-03] 1·2번 개발 방향에 '정렬'로 잘못 기재(탐색 문항).
- [12정02-04] 수행평가 채점표 2번 E 행 문장이 3번 성격 문장("가설 지지 여부를 언급하고…").
- [12정05-03] 수행평가 분할점수 원문 "13 10 9 4 6"(D/E < E/미도달 역전). 채점표 합산 시 13/10/9/6/3.
- [12정03-07] 논술 예시 답안의 "2의 배수 조건 이후 else문이 연결" 표현은 코드상 정확히는 공배수 if에 else가 연결됨.
