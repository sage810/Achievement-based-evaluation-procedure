# 평가계획서 검토 절차 (Claude Code용)

앱 「평가계획서」 탭에서 선생님이 계획서(PDF·HWP·HWPX)를 올리면 「검토 대기」로 쌓인다.
선생님이 Claude Code에 **「평가계획서 검토」**라고 하면 아래 순서로 검토하고 결과를 앱에 넣는다.
검토 항목은 `data/review-template.json` (원본: `docs/평가계획서 검토 템플릿.xlsx`, 결과 내려받기 양식: `data/templates/`).

## 순서
1. 개발 서버가 켜져 있는지 확인(`npm run dev`, API 8000).
2. `py -3.12 tools/plan_review.py pending` — 대기 목록.
3. `py -3.12 tools/plan_review.py text <id>` — `data/plans/<id>.txt` 로 글자 추출 후 **전부** 읽는다.
   PDF는 글자 사이에 띄어쓰기가 끼어 나올 수 있다(「사 물 인 터 넷」) — 공백을 지우고 대조한다. 표가 깨져 판단이 어려우면 원본(`data/plans/<id>.pdf`)을 직접 본다.
4. 계획서의 학교급·과목을 확인하고 원문을 불러온다:
   `GET http://localhost:8000/api/standards?school_level=고등학교&subject=정보` (성취기준 코드·진술·A~E 성취수준).
   공백을 모두 지운 문자열로 계획서의 진술과 대조해 **다른 성취기준의 진술이 들어간 곳**을 찾는다(페이지 경계로 끊긴 것은 오류 아님).
5. `data/review-template.json` 의 38개 항목(취지 점검 가1~라3, 지침 점검 1~26)을 하나씩 판정한다. 계산 항목(반영비율 합, 영역 만점 = 요소 최고점 합, 기본점수 = 요소 최저점 합, 기본점수 20% 이상 40% 미만, 장기 미인정 결석 = 기본점수 − 1, 배점 등간격·소수점, 기준 성취율 90·80·70·60·40)은 **직접 다시 계산**한다.
6. 결과 JSON을 `data/plans/<id>.review.json` 으로 쓰고 `py -3.12 tools/plan_review.py save <id> data/plans/<id>.review.json`.
7. 선생님께 요약(✖ 개수, 가장 먼저 고칠 필수 항목)을 알린다. 앱 화면은 10초 안에 저절로 바뀐다.

## 판정 기준
| 값 | 표시 | 쓰는 경우 |
|---|---|---|
| `bad` | ✖ 문제 | 필수 항목 위반, 계산이 틀림, 원문과 다름, 성취평가 취지에 어긋남 |
| `warn` | △ 고민 필요 | 권장 항목 위반, 판단이 갈리거나 개선을 권함, 근거 자료(학사일정 등)가 없어 확정 못 함 |
| `ok` | ✔ 잘 됨 | 확인했고 문제없음 |
| `na` | － 해당 없음 | 계획서에 그 부분이 아예 없음(예: 주별 교수학습 운영 계획 미포함) — finding에 무엇이 없어서인지 적기 |

## 항목마다 쓰는 것
- `where`: 계획서에서 찾은 위치 — 「4번 표 · 빅데이터 영역」「6번 · 제어 구조 프로그램 · 자료형 선택하기」처럼.
- `finding`: 무엇이 어떻게 되어 있는지 **수치·인용으로**(「요소 배점 8+8+10=26점인데 영역 만점 25점」). 잘 된 항목도 무엇을 확인했는지 한 줄.
- `fix`: 고칠 방향이나 바꿀 문구(「상단 기본점수를 10점으로」「C수준을 원문 '데이터를 시각화하고 …인식할 수 있다.'로」). ✔면 비워도 됨.
- `summary`: 3~6줄. 총평 + 가장 먼저 고칠 필수 오류. 줄바꿈(\n)으로 구분.

```json
{ "summary": "…", "items": { "가1": { "verdict": "bad", "where": "…", "finding": "…", "fix": "…" }, "1": { … } } }
```
