# skill-guide — 스킬 골라서 확인받고 적용

**선생님이 계획을 고르기 전에는 아무것도 고치지 않는다.** (파일 읽기·검색은 괜찮다)

## 순서

1. **요청 파악** — 앞의 `?`·`스킬:` 표시는 떼고 읽는다. 표시만 있고 요청이 비어 있으면 무엇을 할지 먼저 묻는다.
2. **후보 찾기** — `.claude/skills/*/SKILL.md` 의 앞부분(name·description)만 훑는다(이 스킬은 빼고).
   폴더를 기준으로 찾으니 스킬을 새로 넣어도 저절로 후보에 들어간다.
3. **후보 본문 읽기** — 쓸 만한 스킬 2~4개의 SKILL.md 본문만 읽는다. 그리고 이 저장소 규칙을 확인한다:
   `.claude/external-skills.md`(외부 스킬 활용·우선순위) · `.claude/napkin.md` · 디자인이 걸리면 `docs/rules/design.md`.
4. **계획 2~3개 만들기** — 계획 하나는 스킬 하나 또는 조합(예: `lesson-edit + better-writing`). 계획마다:
   - **무엇** — 스킬이 하는 일 한 줄
   - **이번엔** — 이 요청에서 실제로 할 일. 차시·파일·범위를 구체적으로.
   - **조정** — 스킬 원래 방식에서 이번에 바꾸거나 빼는 것 + 이유
     (예: better-colors 의 새 팔레트 제안은 빼고 대비 검사만 — `design.md` 토큰 우선). 없으면 "없음".
   - **결과물** — 끝나면 무엇이 남는지(고친 파일 · 검수 목록 · PDF …)

   가장 맞는 계획을 맨 앞에 두고 label 끝에 `(추천)`. 마지막 선택지는 항상 **스킬 없이 바로**.
   맞는 스킬이 하나도 없으면 선택지를 **스킬 없이 바로** / **이 일을 새 스킬로 만들기** 로 둔다.
5. **묻기** — AskUserQuestion 한 번에 묻는다.
   - Q1 "어떻게 할까요?" — 계획마다 선택지 하나(최대 4개). label = 스킬 이름(조합), description = "이번엔" 한 줄,
     preview = 무엇·이번엔·조정·결과물 카드.
   - Q2 — 추천 계획에 **조정**이 있고, 그 조정이 이번 요청만이 아니라 이 저장소 전체에 해당할 때만.
     "'<조정 한 줄>' 을 어디까지 적용할까요?" → **이번만** / **앞으로도**(description 에 저장 위치: 7번).
     고른 계획에 그 조정이 없으면 Q2 답은 무시한다.
6. **실행** — 고른 계획대로.
   - 스킬은 Skill 도구로 부른다. `disable-model-invocation: true` 인 스킬(interface-review · i-have-adhd 등)은
     Skill 도구로 못 부르니 그 SKILL.md 를 읽고 절차를 그대로 따른다.
   - "이번엔"·"조정" 에 적은 범위를 넘지 않는다. 하다가 범위를 넓혀야 하면 다시 묻는다.
   - 각 스킬 자체의 확인 단계(lesson-new 의 단계별 확인 등)는 그대로 지킨다.
   - "새 스킬로 만들기" 를 골랐으면 `.claude/README.md` 의 스킬 만드는 법대로 하고 표에 한 줄 추가한다.
7. **"앞으로도" 를 골랐으면** — 실행이 끝난 뒤 저장한다.
   - **우리 스킬(`lesson-*` 등 LICENSE 없는 폴더)** → 그 스킬의 `SKILL.md` 나 `references/` 를 고친다.
     바꿀 부분을 먼저 보여 주고 확인받은 뒤 고친다.
   - **외부 스킬(LICENSE 있는 폴더)** → 원본은 고치지 않는다. 새 판으로 폴더째 덮어쓰면 사라지고,
     "원본 그대로 + LICENSE" 방침(`external-skills.md`)과도 어긋난다. 대신 `.claude/napkin.md` 의 알맞은 분류에
     napkin 형식(`**[날짜] 상황**` + `Do instead:`)으로 한 줄 추가한다.
